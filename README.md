# LIGHTS OUT · 1250 米极限刹停

中文单车 F1 冲线与精准刹停挑战。五组双红灯熄灭后，使用右侧油门手动加速、左侧刹车控制速度，支持双指或键盘同时踩两个踏板；在不超过 250 km/h 的前提下，尽快冲过 1250 米终点线。冲线后动力自动切断，在终点线后 250 米的黄黑路障前停稳，车头越靠近路障越好。

## 当前规则

- 竞速赛段 **1250 米**，路障位于 **1500 米**。前半段必须自己按住油门加速，松开后缓慢滑行，再按可以继续加速。
- **250 km/h 是爆缸界限**：恰好 250 时松开油门仍安全，继续加速会引擎爆炸并失败。240 km/h 起仪表显示红色提醒，需自行通过收放油门控制速度。
- 车头穿过终点线的瞬间锁定**冲线时间**，从灯灭开始计算，包含起步反应。后续滑行、刹车的时间不会改变冲线分或冲线排名。
- 刹车与油门是两个独立踏板，**左刹车、右油门**。电脑 **W 油门、S 刹车**，可同时按；空格、右方向键油门和左方向键刹车仍兼容。触屏分别捕获每根手指，松开一个踏板不会释放另一个。
- 冲线前可同时踩油门和刹车，动力与制动力共同作用；踩刹车不会永久切断动力，松开刹车仍能继续加速。松开刹车时压力正常卸载。
- 冲线后自动、永久切断动力，右油门禁用；左刹车保持独立控制，原本按住油门不会自动制动，原本按住刹车则继续制动。松开左刹车只会滑行，再按继续刹车。
- 在终点线前正常减速至 **0 不结束本局**，计时继续，可再踩油门起步；尚未过线时不会生成冲线时间或成绩。只有冲过终点并在路障前正常停稳才有综合得分。
- 使用游戏化的 **8 挡自动变速箱**：54 / 88 / 120 / 151 / 180 / 207 / 232 km/h 依次升挡。升挡有 **90 ms** 动力中断，车辆在此期间轻微减速；转速随挡位真实回落。降挡采用更低的独立阈值，避免收放油门时反复跳挡。
- 松开油门或冲线后，基础滑行减速度 **2.2 m/s²** 加上按挡位计算的发动机制动；8 挡为 **2.6 m/s²**，随自动降挡逐步增强，1 挡为 **4.0 m/s²**。手动刹车时也计入发动机制动，踩油门时则由动力和制动力共同作用。
- 仪表显示当前实际挡位、转速灯带及千转数，升降挡时短暂显示“升挡”或“降挡”。电脑仍为 W 油门、S 刹车。
- 压力建立比上一版加快 **三分之一**，按实时车速增长：每秒 `25 + 100 × (当前 km/h ÷ 250)` 个百分点；松开每秒卸压 100 个百分点。
- 压力 **100% 时仍能制动，达到 115% 且仍在行驶才会锁死打滑**。这是“打滑压力再加 15%”的实现方式；未改为真实轮胎摩擦模型。
- 成功停车的距离分以**车头到 1500 米路障前表面的距离**计算，越近越好。车头接触路障或刹车锁死打滑仍为失败，0 分且不可上榜。
- 碰撞后先播放 **2.6 秒**路障撞飞、翻滚、火焰、火花与烟尘，再显示结算；碎片方向、速度及旋转每次随机，冲击强度随碰撞速度变化。引擎爆炸在车身位置播放火焰、火花和烟雾，路障保持原位。复用现有模型与特效，不新增重型素材。效果与赛果计时分离，重试恢复整排路障并清除特效。
- 横跨车道的黑白棋盘格标线加宽至 **9 米**，六排 1.5 米方格增强黑白对比，贴合沥青并接受光照和阴影。标线朝向来车的近端与 1250 米冲线平面对齐；赛道、红白护栏、建筑与树木延伸到新路障后方。
- 写实护栏和铁丝网的近景段与远景段共用赛道长度计算，覆盖 1500 米路障后 220 米，修复延长赛道后近景模型仍停在旧终点附近、导致左右护栏消失的问题；保留原有模型池容量和按距离筛除。
- 赛道两侧不再摆放黑色米数距离牌，剩余距离由行驶仪表显示。
- 行驶距离与起步反应 / 冲线时间放在画面**顶部正中**，采用透明背景、白色大字和文字阴影，提升浅色建筑前的可读性。界面统一为黑、白、赛车红。
- 五组双灯使用现成灯具网格，横向放大 35%、纵向放大 18%，居中安装在发车横梁上。竖屏视野保持至少 42° 水平视角，保证五组灯完整显示。
- 灯灭且允许起步时整屏闪过半透明绿色（26% 不透明度），320 ms 线性淡出；无文字提示，不阻挡踏板操作。每轮只触发一次，即使油门事件早于下一帧渲染也会触发。减少动画偏好下缩短为 160 ms。
- 终点复用已下载的横梁网格，增加黑白 FINISH 标识；冲线后两侧向上喷出金白火花，粒子池复用，仅增加两次绘制调用，结束与重试均自动清理。
- 提前起步算抢跑，灯灭后 10 秒未起步算超时。切走页面会取消本轮。每次重试完整重置动力、压力和统计。

## 赛后数据

有效刹停、爆缸、打滑和碰撞均有结算面板；终点线前正常停车继续比赛。未起步或未刹车的数据用“—”显示，不生成虚构曲线。

- 车头距路障的停车距离；冲线时间和起步反应分行，起步反应字号加大。未冲线的回合只显示“未冲过终点线”，不以提前停车时间代替冲线时间。
- 冲线时间、制动距离、最高刹车压力并排显示；冲线时间卡片只取过线瞬间，不显示提前停车时间。
- 加速过程图显示起步至冲线的白色车速曲线，不显示油门线、油门图例或百分比坐标。线前停车及重新加速也记入同一曲线；爆缸曲线止于本轮结束并保留实际速度。
- 从首次刹车开始记录速度与压力曲线，包括松开踏板后的滑行，红虚线标出 115% 打滑阈值。
- 碰撞曲线保留实际碰撞速度，不画成正常减速到零。
- 结算页同时展示两张曲线、三项统计、停车距离、起步反应、综合得分和记录/重试按钮。布局随屏幕调整，并按可用高度整体缩放；不用滚动才能看到底部内容。
- 综合得分以加大字号展示，使用距路障 50%、冲线时间 30%、起步反应 20%；只有冲线并有效刹停的回合才有分，失败为 0 分。计算为：

  `50/(1+距路障cm/500) + 30/(1+冲线ms/20000) + 20/(1+反应ms/300)`

此处展示游戏实际使用的**压力百分比**，不虚构牛顿力度、刹车踏板断裂或车辆翻滚数据。


将本目录的内容上传到仓库根目录，保留 `assets/`、`vendor/`、`src/`、`styles.css` 和 `index.html` 的相对位置。**不能只替换 index.html**。

## 在线排行榜与部署

冲过终点线且在路障前正常停稳才可上榜；用户主动点击“记录成绩”、填写昵称并提交后，昵称与成绩会公开显示。全部设备读取同一份在线榜，页面打开时同步，每 15 秒自动刷新，也可点击刷新。新成绩持久保存在 Vercel 私有 Blob 中，重新部署不会清空。

排行榜分为**距路障、起步反应、冲线时间、综合得分**四栏，各自独立排序，每栏先显示前 5 名，其他名次可在栏内滚动查看，表头保持可见；前三项越小越好，综合得分越高越好。每位玩家在每栏只出现一次，取其此项最佳回合；相同数值并列排名。综合分按展示的两位小数判定并列。匿名玩家以签名 HttpOnly、SameSite cookie 标识；同名不同玩家可分别上榜。清除 cookie 或换浏览器会成为新的匿名玩家，不会删除原有线上成绩。无需注册或提供真名。

服务器签发与玩家绑定的有效期凭证，接收操作记录后使用相同物理规则重放并计算距离、冲线时间和得分。拒绝爆缸、碰撞、打滑、无效操作、篡改结果及不合理计时。每张凭证仅对应一条不可覆盖的成绩，重复提交返回原记录；并发提交不会覆盖其他玩家。此校验并非完整的竞技反作弊系统，客户端操作仍可能被自动化。

在线数据仅使用 `sprint250-v11`（250 米刹停区）。旧的 500 米赛制及在线成绩已移除，后台只管理当前赛制。旧 localStorage 的 v10、v9、v8 等记录不会自动公开或导入新榜。

Vercel 部署：运行 `npm ci` 后执行 `vercel deploy --prod`。项目必须连接 **private** Blob，服务端环境变量为 `BLOB_READ_WRITE_TOKEN`，密钥不得放到前端或提交到 Git。无需创建额外数据库账户。`npm run build` 只将游戏静态文件复制到 `public/`；`api/` 是独立 Node.js 函数，`server/` 和环境文件不会进入静态目录。`POST /api/runs` 签发本轮凭证，`POST /api/leaderboard` 校验并提交，`GET /api/leaderboard` 返回四项排名所需的各玩家最佳成绩。

Blob 使用不可变的单局记录及私有列表索引；读取时分页扫描索引并只返回每位玩家四项最佳回合，短时缓存减少重复读取。本方案适合当前小游戏规模；大量玩家和长期高频挑战时，应迁移到支持索引查询的数据库。

## 密码成绩后台

入口为部署站点的 **/admin/**。服务端环境变量 `ADMIN_PASSWORD_HASH` 保存随机盐 scrypt 哈希；浏览器静态文件不包含管理密码或密码哈希。密码通过 HTTPS 提交到同源登录接口验证，签发 8 小时有效的 HttpOnly、Secure、SameSite=Strict 会话。更换密码哈希会使旧会话失效。登录尝试按 IP 的 HMAC 指纹持久限流（每分钟 8 次），不保存明文 IP。

后台逐局显示当前 250 米规则的全部有效成绩，支持按昵称、玩家编号或成绩编号搜索、分页和刷新。修改昵称、距路障、反应、冲线时间、停车用时后，服务端重新计算距离方向与综合得分；不能修改玩家身份。公开榜会在下一次刷新（最多约 15 秒）同步。

删除会移入回收站，可恢复；其余回合继续参与每位玩家的最佳成绩排名。管理记录保留最近 200 次操作，界面显示最近 30 次。并发修改通过存储 ETag 和记录版本校验，避免静默覆盖；原始比赛记录保持不变，重复提交也不会撤销后台修改。

`GET/POST/DELETE /api/admin-session` 查询登录、登录和退出；`GET/PATCH /api/admin-scores` 每次均校验登录，管理请求校验来源与字段。接口只读写当前赛制；携带已停用赛制的请求返回 410，不能读取或修改其他存储路径。

## 模型、实拍纹理与光照

没有创建新的车、路障、赛道或灯具模型。使用下载的现成模型，进行复制摆放、材质调整、现成部件组合及网页网格优化；没有重新建模。

- 赛车：**F1 2022**，Blender458，CC BY 4.0；沿用原项目由 FetchCFD / [RM-RAIN-MASTER](https://github.com/Pilot123321/RM-RAIN-MASTER#credits) 获取的模型。合并绘制，调整车漆、金属、轮胎材质，保留原网格形状。
- 赛道、看台、远景护栏和发车灯：[Kenney Racing Kit](https://kenney.nl/assets/racing-kit)，CC0，沿用原项目。
- 近景混凝土护栏：[Concrete Road Barrier 02](https://polyhaven.com/a/concrete_road_barrier_02)，Poly Haven，CC0。扫描网格从每段 23,822 个三角面优化至 3,622 个；保留原尺寸实拍法线与粗糙度，使用从混凝土照片生成的红白油漆涂装，保留坑洞与磨损。沿赛道红白交替，远景代理同步颜色与尺寸。原始资源保留供修改使用，页面只加载 _web 版本。
- 铁丝网：[Modular Chainlink Fence](https://polyhaven.com/a/modular_chainlink_fence)，Poly Haven，CC0。选取现成直线模块，立杆由 3,024 个三角面优化至 1,007 个，网片全部 30 个原三角面保留。官方透明遮罩、法线、金属和粗糙度贴图保持原尺寸；透明裁剪和 alpha to coverage 减少网片排序闪烁。
- 建筑后方树木：[Jacaranda Tree](https://polyhaven.com/a/jacaranda_tree)，Poly Haven，Rico Cilliers / Rob Tuytel，CC0。完整原模型离线渲染为多角度无损 WebP 树冠图集，运行时按视角显示；附近使用同一模型优化后的网格投射实时阴影。树冠采用预渲染光照，适用于固定太阳和赛道相机，近距离自由观察仍有视角限制。
- 维修区卷帘门：[Rollershutter Door](https://polyhaven.com/a/rollershutter_door)，Poly Haven，CC0。使用无涂鸦版本的现成网格及金属、污渍、凹凸纹理，装配在原有车库正面。
- 终点标线：参考 [Getty Images 的真实赛道终点线照片](https://www.gettyimages.hk/%E5%9C%96%E7%89%87/race-track-finish-line) 中的横向黑白棋盘格路面标线；使用现成 Kenney 赛道路面网格的薄层副本调整材质与 UV，叠加沥青法线和粗糙度。
- 黄黑路障：[Traffic Barrier](https://poly.pizza/m/cM3aJPU9NS)，**Quaternius**，CC0。保留 A 字架和斜纹网格，改为黄黑配色，复制原有横板部件组成双横板，整排摆放在终点线后 250 米处。
- 圆形警示灯：[Kenney City Kit — Roads](https://kenney.nl/assets/city-kit-roads)，CC0。使用 construction-light 原模型的圆形灯头部件，旋转、缩放并调整琥珀色发光材质。
- 赛道沥青：[Asphalt Track](https://polyhaven.com/a/asphalt_track)，Poly Haven，CC0，实拍色彩、法线与粗糙度贴图。
- 混凝土：[Concrete Wall 001](https://polyhaven.com/a/concrete_wall_001)，Poly Haven，CC0。
- 草地：[Aerial Grass Rock](https://polyhaven.com/a/aerial_grass_rock)，Poly Haven，CC0。
- 金属表面：[Rusty Painted Metal](https://polyhaven.com/a/rusty_painted_metal)，Poly Haven，CC0，使用法线与粗糙度细节，未给车漆叠加锈色。
- 环境：[Autumn Field PureSky](https://polyhaven.com/a/autumn_field_puresky)，Poly Haven，CC0，1K HDR 环境、反射及天空背景。
- Three.js **0.160.1** 及其 GLTFLoader、RGBELoader、BufferGeometryUtils，MIT，来自官方 npm 包。
- Barlow Condensed ExtraBold 字体，SIL OFL 1.1，沿用原项目。

使用 PBR 材质、HDR 环境反射、暖色斜射太阳与冷色天空补光、柔和阴影和 AgX 色调映射，保留亮部细节。桌面使用 2048 像素 PCF 阴影，手机使用 1024 像素 PCF 阴影；移动阴影相机对齐阴影纹素以减少闪烁。围栏和灯杆使用金属材质，墙体使用混凝土，避免混用；建筑后恢复基于真实树木模型的树冠与投影。原有赛道和看台的几何轮廓仍带有低多边形风格。

写实护栏和铁丝网使用实例化移动细节池；仅车辆附近提交优化后的详细网格，远处恢复轻量代理。静态实例按距离筛除雾后和车后的不可见物体；远处相同模型仍正常显示，但不重复进入近景阴影绘制。静止首页和结算镜头结束后复用已渲染画面；灯光变化、移动、碰撞及窗口调整会重新绘制。仪表数值只在变化时写入 DOM，减少布局和垃圾回收负担。

本轮优化保留原有像素比上限、贴图尺寸和阴影分辨率：桌面 DPR 上限 1.75 / 2048 阴影，手机 DPR 上限 1.5 / 1024 阴影。手机保留原来的较短细节范围。所有素材均在本地 assets 内，页面不依赖素材站在线加载。

右侧维修建筑移除 TANKCO 广告面，并取消与自带办公室的屋顶模型重复叠放的办公室层，修复共面表面在移动时闪烁的问题。

下载来源、字节数及 SHA-256 见 `assets/manifest.json`，许可原文与署名见 `licenses/`。本项目为非官方 F1 主题体验，不代表 Formula 1、车队或素材作者背书。
